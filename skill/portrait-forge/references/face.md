# 面部设计：关系先于形容词

字段候选见 [字段目录](../assets/fields.json)。枚举是便于比较的创作语言，不是人体测量或审美评分。先选已锁定值，再从自由轴组合。

| 层 | 设计内容 | 容易混淆的两件事 |
|---|---|---|
| 整体 | 长宽、中庭占比 | 全脸长不等于每一庭都长 |
| 眉眼骨架 | 眉骨起伏、眼窝深度 | 眉毛弧度、眼皮褶皱不代表骨架 |
| 颧部 | 高度、横向宽度、向前体量 | 高颧不必宽，阴影不等于骨点 |
| 下颌下巴 | 相对颧宽、转折、形状、长度、前后位置 | 短不等于后缩，尖不等于前伸 |
| 软组织 | 面颊覆盖与过渡 | 瘦削不是高骨相的同义词 |
| 五官 | 眼裂/开合/间距/眼睑/方向，鼻梁/鼻背/鼻尖，唇比例，原生眉 | 化妆和表情形成的变化不反写进原生结构 |

原创必须给眉眼、颧部、下颌下巴三个区域具体关系；既允许平缓浅眼窝，也允许明显起伏。正面观察不足以恢复面中前后结构，此项在字段目录中为可选。

肤色、微纹理和标记独立于结构。保留用户指定肤色；不把清透变成提白、不把写实变成满脸雀斑。没有必要时省略标记。

阵容以 face / contour / eyes / nose / lips / brows 六个独立组比较。一组内多项变化只算一次；骨架颧颌同归 contour，防止重复计数。眼窝和眉骨在编译与锁定范围内，但不额外加组得分。肤色、妆、发型不能代替脸的差异。默认每对至少三组变化且两组来自 face/eyes/nose；这是内部设计门槛，可按目标预先配置，不是实际辨识率。若需要更明显差异可先设 min_groups=4，不能检查失败后偷偷降阈值。

组合完成后作语义检查：字段各自合法不表示人像描写无矛盾。检查服饰、头发和光影描述是否又包含了相反的脸型或肤色；自由文本只能描述它所属的层。
