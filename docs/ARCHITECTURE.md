# 架构与数据流

自然语言需求 → Agent 判断任务/证据/锁定 → 角色档案 → 合同校验 → 编辑基线比较（按需）→ Prompt 编译 → 宿主图片工具（按需）→ 实际看图复核。

职责边界：

| 模块 | 接收 | 输出 | 不承担 |
|---|---|---|---|
| SKILL + references | 需求、当前上下文、可读图片 | 设计选择和档案 | 不伪装成自动图像测量 |
| assets/fields.json | 人工维护的字段定义 | 枚举、身份标记、分组、中文标签 | 不维护用户角色事实 |
| contracts.py | 档案 | 定位错误、警告、逐对差异 | 不理解自由文本全部语义 |
| revisions.py | 基线、补丁、允许列表 | 新版本、校验后的变化 | 不判定用户授权真实性 |
| compiler.py | 合法档案、必要基线 | 完整 Prompt、字段 trace | 不调用网络或模型 |
| portrait.py | CLI 参数 | JSON 与退出码 | 不覆盖输入文件 |
| tools | 明确目标目录 | 安装副本、阅读包、ZIP | 不发布或自动更改宿主配置 |

没有仓库根 SKILL：工程目录与安装目录分开，用户只需复制 skill/portrait-forge。引用路径均在独立技能内闭合；完整项目文档不是运行依赖。

字段目录为语法真源，用户 JSON 为实例真源，编译结果为派生物。schema.py 生成形状描述；跨字段逻辑仍由 contracts 负责。编译结果不能反向覆盖角色档案，人工修订 Prompt 后应将实际变更回写字段再编译。

设计扩展不依赖图片厂商。需要接入具体模型时在宿主适配层转换图片引用、分辨率和参数，保留实际返回的模型信息；未知则不填。不要将工具参数混入骨相字段。

设计保真度：枚举轴较粗，适合文字设计管理；不用于精确面部测量。自由文本确保表达空间，但也需要语义复核。这种取舍优先让编辑边界可以验证，而不假装通过字符串完全理解审美。
